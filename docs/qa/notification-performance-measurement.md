# 通知処理の性能確認

Botの既存heartbeatにDB問い合わせ時間、X通知の受信からルールへ渡すまでの時間、新着・価格の取得処理開始時の予定時刻からの遅れ、送信予定時刻からDiscordの確認済み送信までの時間を追加する。X受信からルールまでは通常とリアルタイムに分ける。個別のXイベントについては受信から確認済み送信までの時間も記録する。件数、失敗数、合計・最大時間、固定範囲ごとの件数、95パーセンタイルが収まる範囲を出す。集計期間はプロセス起動からの累計であり、再起動時にリセットされる。最大の範囲を超える値が95パーセンタイルに入る場合、上限値は表示せず件数で判断する。DB時間は5分、通知時間は24時間で上限を設ける。SQL、パラメータ、利用者IDや通知本文は記録しない。

既存heartbeatのメモリ・メッセージ処理キュー、既存の通知履歴や稼働状況と合わせ、同一負荷で変更前後を比較する。DB集計はBotプロセスで発行した問い合わせに限り、別プロセスのダッシュボードを含まない。プール接続の総数・使用中・待機数・上限も表示する。接続数は対応するmysqlドライバーのプール内部配列からの観測値で、対応していない実装では未取得とする。計測時間は接続待ちを含むクエリの呼び出しから応答までであり、DBサーバー内部の実行時間ではない。

ダッシュボード側では、管理者が「画面の処理状況」から、そのサーバープロセスのDB・APIの累計を確認できる。API区分は固定され、URLや利用者IDは記録しない。ブラウザーでの表示時間は含まれない。

画面の表示完了時間はこれらの集計だけでは分からない。取得処理の遅れは処理開始時点であり、取得完了時刻ではない。再試行も計上する。個別のXイベントを特定できないまとめ通知はX受信からの時間には含まれない。送信予定時刻はキュー上の時刻であり、確認先の取得予定時刻ではない。ルールへ渡したことはDiscordへの送信成功を意味せず、Discordからの確認は閲覧を意味しない。利用者の行動や通知内容を新たに送信する計測は導入しない。
