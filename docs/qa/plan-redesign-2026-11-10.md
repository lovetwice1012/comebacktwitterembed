# 通知プラン再設計: 実装・移行メモ

これは実装準備中の記録であり、本番反映済みの設定ではない。

通常通知とX監視は同じ個人枠を消費する。寄付による永久追加枠は従来どおり加算し、旧購入は購入回数による付与数を維持する。Xの全体共用無料枠50、支援者優先枠100は独立しており、特殊枠も独立する。既存寄付者が支援者優先枠を利用する場合は1枠で即時通知を選択できる。ベーシック以上は個人共通枠とXの枠に空きがある範囲で、件数制限なく1件1個人枠で即時通知を選択できる。それ以外でも監視1件につき合計5個人枠を使って即時通知を選択できる。

既存寄付者は確定済みの対象者リストに基づく別の永続フラグで識別する。現在の `is_donor` は新旧の寄付者を表すので、全件を既存寄付者に変換してはならない。既存寄付者について既存の登録上限、確認間隔、送信上限、優先度、その他の権利を下げない。個々の契約や既存登録を変更する場合も既得条件を確認する。

## 実装前に確認したこと

- プラン内の即時通知件数上限は設けない。既存の `automation_push_plan_policy.realtime_enabled` を使い、登録・設定変更・解除・枠移動・プラン変更の各経路と監視処理で一貫した権利判定を確認する。
- `src/automation/x-processing-settings.js` と `x-monitor-quota.js` は `users.is_donor` を既存寄付者判定に使っている。新しい判定へ移す際は対象者の確定、追加履歴の監査、後戻り手順が必要。
- `src/automation/entitlements.js` は支援者を独立したプランとして選び、契約プランを優先する。別フラグによる既得条件の重ね合わせには、通常通知とXの両方での権利計算・テストが必要。
- 新着通知・X・価格監視にはプラン確認間隔を適用する。新着通知の利用者別設定は保持し、明示的なテスト用オーバーライドで引き続き利用できる。既存寄付者の切替時は過去の個別設定と監視元の間隔も確認して、元より長くならない条件を保存する。
- 価格監視は共通取得と利用者単位の確認結果を分ける。各利用者の前回確認価格を永続化し、他の利用者による共通取得で価格変化を見落とさない。プラン変更や確認処理中の競合、失敗・再試行も検証する。
- Square本番連携は、対象事業者・環境・月額・通貨・課金周期・Webhookを照合してから有効化する。旧テスト契約の解約はSquare側の契約一覧も確認し、対象が特定できたものだけ実行する。アプリDBの契約件数が0件でもSquare側の契約が0件とは限らない。

## 受入・反映

新旧寄付、全プラン、共通枠、各X枠、対象プランでの件数上限のない即時通知、5枠方式、同時操作、契約切替・解約、既存設定、Webhooks再送、DB障害を実DBと自動テストで検証する。データのバックアップとロールバック、Square側を含むテスト契約の結果確認、実稼働ヘルス確認が必要。実決済や実配送の検証範囲は模擬試験と区別する。
