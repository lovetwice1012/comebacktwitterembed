# プラン変更の反映・復旧手順（準備中）

## 反映前

1. 実行中のリリース、Botとダッシュボードの状態、Squareの事業者・店舗・本番環境、Webhooksを確認する。認証情報の値は記録しない。
2. Square側の全契約をページ送りで検索し、アプリ側の契約・受付中のチェックアウト・管理者による有償プラン割当と照合する。不明な契約や未確定処理があれば移行を止める。既存のテスト契約が見つかれば解約結果をSquareで確認する。
3. 使用中の各プラン、Square連携、寄付残高・履歴、X枠、通常通知と価格監視、通知待ちデータをバックアップし、隔離DBで復元を検証する。バックアップの保管場所や認証情報をログに出さない。
4. 既存寄付者33人と以前提示されたリストを照合する。件数・対象・既存条件に差があれば停止する。永久追加枠の数値を金額から再計算しない。
5. テスト・lint・型検査・UI確認と、配布するコミットの一致を確認する。ソースの取得先、依存関係、永続データ参照先を確認する。

## 切り替え

新しいコードと追加テーブルを用意し、既存データと設定を参照させる。実際のプラン変更は `applyApprovedPlanPolicies` を単一DBトランザクションで実行する。支援者の旧条件を先に固定し、照合の成功後にプランと確認時刻を切り替える。不一致、決済処理中、DB障害、監査ログの書き込み失敗時はトランザクション全体を取り消す。

運用CLI `scripts/plan-redesign-rollout.cjs` は、保護されたファイルに保管した33人分のJSON配列と管理者IDを受け取る。`preview` は同じ変更をトランザクション内で実行して取り消し、`apply` は確定する。`stage-square` は切り替え後に月額料金を照合・作成し、購入受付を停止した状態で記録する。初回実行前に、プレビュー後のDBとSquareに書き込みがないことを確認する。

Squareの料金は本番事業者、JPY、MONTHLY、130・400・980・1,480円をそれぞれ確認して紐付ける。**有料プランの購入受付は停止したままにする。** 旧ウルトラのDAILY 330円は新月額料金として使用しない。通信結果が不明な料金作成は、既存の作成記録とSquareの結果を照合し、再作成して重複させない。Xの支援者限定公開も維持する。

反映後は実行中のリビジョン、サービスの稼働状態、既存寄付者の特典・追加枠、プラン値、監視件数、Squareの月額・通貨・連携状態、待ち通知とエラーを確認する。実際の決済やDiscord送信を行っていない場合、それらの成功を主張しない。

## 復旧

切り替えトランザクションの失敗時はDBの自動ロールバックを確認し、旧リリースを再開する。切り替え完了後は、新しい寄付・契約・監視・通知履歴を上書きしないよう、旧コードへ戻す前にアクセスとワーカーを止め、現在の状態を別にバックアップする。変更後に発生したデータと契約を照合してから、監査付きの補正で旧ポリシーへ戻す。稼働中のDBへ古い全体バックアップを上書きしない。

Squareの料金作成・連携はDBとは別サービスのため、DBロールバックだけでは元に戻らない。作成済み料金と既存・新規契約をSquareで照合し、購入受付停止や必要な契約処理を別途行う。未確定の操作は結果を確認するまで再送しない。
