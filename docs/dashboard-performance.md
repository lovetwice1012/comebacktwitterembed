# ダッシュボードの性能改善（2026-09-05）

分析項目・集計期間・設定項目を維持し、集計の結合方法、設定の読込回数、レポート確認時のコピー、キャッシュとDB接続の保持を改善した。先行するBot側の改善と既存のDB修正は保持している。本番への反映は行っていない。

## 分析クエリ

関心分析は、同じユーザーの投稿を1件ずつ別の投稿と結合していた。変更後は、対象側を「ユーザー・プロバイダ・アカウント・サーバー」、比較側を「ユーザー・プロバイダ・アカウント・コンテンツ種別」にまとめてから結合する。

各組の投稿件数を掛け合わせて加算することで、元の投稿の組合せ件数を維持する。共有ユーザー数・サーバー数も従来通りDISTINCTで求める。NULLや空のアカウント、日付境界、サーバー/プロバイダ/ユーザー/コンテンツ/ファセットのフィルタについて、元のSQLと新しいSQLを実行して結果を比較した。新規テーブルやマイグレーションは不要。

レポート内のPromise.allが入れ子になっても、実際に発行中の分析SELECTをプロセス内で最大4件に制限する。レポート構築の既存の上限（実行1件、実行を含め最大4件）は維持し、ルートと起動処理の別バンドル間でも同じ状態を共有する。設定の保存に使う接続プールを分析だけで占有しないようにした。SELECTの項目や返すレポートのセクションは減らしていない。

## 設定画面

プロバイダ一覧と横断設定画面では、プロバイダごとの繰り返し読込をやめ、必要なテーブルごとにサーバー内の全プロバイダ分を取得する。生の設定値を取得した後の既定値・警告・依存関係の処理は従来と共通。読込は最大4クエリを並行実行する。

有効プロバイダ数だけが必要なサーバー一覧用の処理では、enabled列とプロバイダの既定値だけから同じ件数を求める。設定値の長期キャッシュは追加していないため、設定更新後の再読込はDBから新しい値を取得する。

## キャッシュ・画面側の処理

- 生成時点でJSON化できる値へ変換済みのレポートを、確認リクエストごとに全件コピーしない。応答生成ではキャッシュ状態だけを追加する。
- 保存済みレポートの読込Promiseを共有する。25件の同時アクセスでもDB読込は1回で、全リクエストが保存済みレポートを利用し、不要な新規集計が始まらないことを確認した。読込失敗は次回再試行でき、遅れて届いた古い保存データで新しいレポートを上書きしない。
- レポートキャッシュは各種12エントリを基準とし、新しい条件の追加時にも不要なエントリを整理する。実行中の構築は保持する。期限切れのレポートを開いた際は既存の結果を返しながら更新する。
- Discordの利用者別サーバー一覧キャッシュは最大256件。期限切れの整理と取得失敗後の再試行を追加した。アクセストークンそのものをキャッシュキーとして保持しない。既存の権限確認・現在のメンバー確認は維持する。
- Prismaインスタンスを本番でも共有し、別バンドルによる接続プールの重複生成を防ぐ。
- 管理画面の自動確認は「適用した検索条件」を使う。フォームの入力途中の値から別の集計を発生させない。概要タブの確認リクエストは、そのタブが表示されている間に行う。
- ブラウザのサーバー選択一覧で、1回の通信失敗が以後すべての読込を失敗させ続ける問題を修正した。
