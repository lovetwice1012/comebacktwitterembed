2026-10-14にWindows 11 build 26200で実施した、Node.jsの子プロセス起動と最初のTCP接続の比較記録です。アプリ本体、DB、ブラウザーの利用者データ、外部サービスは使用していません。

| 実行環境 | 完了した起動回数 | 成功 | ネイティブ異常終了 | その他の失敗 |
| --- | ---: | ---: | ---: | ---: |
| Node.js 24.15.0 / libuv 1.51.0 | 1,000 | 998 | 2 | 0 |
| Node.js 24.21.0 / libuv 1.52.1 | 1,000 | 1,000 | 0 | 0 |

両方で同じソースを使用し、デバッガーなし、各版2並列、合計4並列で実行しました。各子プロセスのHTTP接続は127.0.0.1への1回だけです。Connection: close、テスト終了後のサーバー解放、テストの10秒制限、プロセスの20秒制限を設定しています。TIME_WAIT数は開始前89、終了後1,597でした。EADDRINUSE、タイムアウト、通常のfetchエラーは発生していません。

旧版の804番と865番の試行では、子プロセスが3221226505（0xC0000409）で終了し、テスト結果は0件、stderrは空でした。該当TAPと全2,000試行のNDJSONを保存しています。summary.jsonとの件数一致、試行番号の重複がないこと、両版の実行ソースSHA256一致を確認してからこの記録を作成しました。

先行する30接続の比較試験は、一時ポート不足による通常の接続失敗を含んでいたため、この集計には含めていません。別途採取された旧版のダンプではFAST_FAIL_STACK_COOKIE_CHECK_FAILURE（引数2）とuv__tcp_connectのフレームが確認されています。ダンプ本体は秘密情報を含む可能性があるため、このディレクトリには保存していません。

原因の参照先は、[旧版のWindows TCP実装](https://github.com/nodejs/node/blob/v24.15.0/deps/uv/src/win/tcp.c#L697-L709)、[OSVERSIONINFOWの初期化修正](https://github.com/libuv/libuv/commit/aabb765)、[Node.jsへの取り込み](https://github.com/nodejs/node/pull/62561)、[24.21.0の修正済み実装](https://github.com/nodejs/node/blob/v24.21.0/deps/uv/src/win/tcp.c#L50-L63)です。旧版ではWindowsのバージョン取得前に構造体のサイズが初期化されず、スタック破損につながります。24.21.0はサイズと文字列先頭の初期化を含みます。

再実行は、空の専用フォルダーに3つのソースファイルをコピーし、指定するNode.jsで `make-mods.mjs`、続けて `run-single-stress.cjs 1000 2` を実行します。結果は版別・実行時刻別の新しいフォルダーへ保存されます。同時実行の合計は4並列以下にし、一時ポートに十分な空きがある状態で行ってください。
