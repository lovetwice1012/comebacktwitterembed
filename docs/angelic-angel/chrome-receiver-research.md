# Chrome Push 受信の検証メモ

Chrome用のWindows配布ツール、登録画面、暗号化保管、常駐受信ワーカーを実装しています。既定ではChromeの受付・受信は無効です。実際のXアカウントを使った通知とDiscordへの配信は、利用者の希望により後日確認します。

## 確認したこと

Windowsで新規作成した一時Chromeプロファイルとローカル試験サイトを使用し、ChromeがWeb Pushの購読を作成して通知を受信できることを確認しました。Chromeを終了した後、試験用プロファイルのGCM情報と鍵を使ってMCSにログインし、その後に送信した別の試験通知を受信・復号できました。購読の公開鍵と認証情報は、保存された秘密鍵と一致することを検査しています。試験は実際のFCMを利用しますが、XやDiscordは使用しません。

Chromiumは製品のcategoryが登録時の値に一致する場合に限り、アプリ識別子としてsubtypeを信頼します。この条件と送信元の照合を両方満たすメッセージのみを対象とします。受信接続にはプロファイル共通の情報が必要なので、他のサイトの通知が到着する可能性があります。

配布ZIPを実際に展開し、専用Chromeで作成した試験購読からファイルを作成しました。登録画面と同じサーバー処理へ手動アップロード相当の操作を行い、暗号化保存、FCMからの受信、隔離MariaDBへの保存、既存ワーカーによる通知ジョブ作成まで確認しました。ローカルの試験サイトをXと同じoriginとして動かした合成データであり、実際のX購読・Discord配信の検証ではありません。ほかのサイトの通知がある場合、明示的な許可がなければファイルを作らないことも確認しました。

対象の暗号化データと再送IDは同時にDB保存し、その後に受信確認します。保存失敗とlease期限切れで両方がロールバックされること、再起動相当のストア再作成と他ユーザーの拒否を実DBで確認しています。送信失敗と再接続時のID引き継ぎはモックによる単体試験です。PCとスマートフォン幅の登録画面はローカルブラウザーで表示・操作を確認しています。

隔離した Alpine Linux 3.24.4・Node.js 24.22.1 では、MCSと端末確認の単体試験27件に加え、Windowsの試験専用Chromeが作成した購読情報を標準入力だけでLinuxプロセスへ渡し、Googleへの端末確認と暗号化通知の受信に成功しました。このLinux実接続試験の受信ストアはメモリ上の試験用実装で、Linuxの本番DBやDiscord配送まで確認したものではありません。

差分のセキュリティレビューでは、初期実装のChromeデバッグ用TCPポートに別プロセスが認証なしで接続できる問題を確認しました。配布版はChromeとの通信を継承されたパイプへ変更し、ローカルの仲介接続は専用フォルダー内で保護した使い捨ての認証情報と限定された操作だけを受け付けます。修正後、別プロセスによるデバッグ接続と任意コマンドを拒否しつつ、試験購読の取得とファイル作成ができることを確認しました。別Windowsユーザーを使った実証は行っていません。

## 未実装・未検証

- Chromium の端末確認は実装済みで、試験専用プロファイルを使いGoogleへの実接続を確認しました。次回間隔と確認時刻の引き継ぎ、認証拒否時に既存購読を保存したまま再登録待ちとする動作も隔離DBで試験済みです。数日以上の連続稼働による長期維持は未確認です。参照: https://github.com/chromium/chromium/blob/main/google_apis/gcm/engine/checkin_request.cc
- 試験用Chromeの再起動時には古いサーバー接続が表示上は接続中のまま通知を受け取れないケースを再現しました。専用ChromeのMCS受信接続先の制限と名前解決の制限を併用した後は、初回購読とファイル作成ができ、Chromeを開いたままサーバーで通知を受信し、ブラウザー側では受信しないことを試験サイトと実FCMで確認しました。二つ目の名前解決制限だけでも同じ試験を通過しています。同じファイルの再登録によって該当接続が再確立し、次の通知を受信・処理することも確認しています。接続情報の長期的な失効、長時間運用、および複数のChrome版での実機検証は残っています。
- 実際のX購読・通知・Discord配送。利用者の実アカウントや既存Chromeプロファイルは検証に使用していません。
- 本番移行前の承認、マイグレーション実施、支援者限定の設定と稼働確認。実行手順は `docs/operations/chrome-x-notifications.md` を参照してください。

三つの `20261110` Chrome関連マイグレーションは本番未適用です。隔離MariaDBでは既存Firefoxデータを保持したまま繰り返し適用し、受信確認用テーブルのロールバックを検証しました。

## 試験

`scripts/test/chrome-mcs-*.test.js` と `scripts/test/chrome-x-transfer.test.js` はGoogleの通知サーバーに接続しない単体試験です。接続を伴う検証は `experiments/chrome-push/controlled-fixture.cjs` と `packaged-e2e.cjs` を使います。後者はWindows、Chrome、ビルド済み `packages/angelic-angel/dist`、使い捨てMariaDB、および試験用の `web-push`、`chrome-remote-interface` が必要です。試験用の新規プロファイルのみを作り、既存プロファイルにアクセスしません。
