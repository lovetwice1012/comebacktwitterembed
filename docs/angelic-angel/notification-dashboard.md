# 自動通知ダッシュボードの構成

## 通知を探す・追加する

通知一覧には、新着通知、価格通知、X通知をまとめて表示する。検索と「種類」「状態」は一覧の絞り込みであり、通知の登録先を分けない。「通知を追加」から通知したい内容を選び、対象、通知先、通知タイミングを確認して登録する。通知先は一覧から開けるほか、登録中にも追加できる。

通常の通知とX通知は既存の登録・変更APIを使い、対象ごとの確認、権限、リビジョン競合、停止・削除の確認を維持する。X通知では、設定用ブラウザーでアカウントごとの投稿通知を有効にし、受信情報を登録する。既存の受信情報がある場合も、追加するアカウントで通知を有効にする必要がある。通知ファイルの内容と他サイトの通知の取り扱いは、アップロード前の同意画面に表示する。

## 一覧の取得と状態

通常通知の新着・価格はそれぞれ独立したカーソルと失敗状態を持つ。X通知は既存の所有者向けAPIから取得する。識別子は通知種別と組み合わせて扱う。部分的に取得できない場合は、取得済みの通知を残して再読み込みできるようにする。画面の「表示中」の件数は、まだ読み込んでいないページの全件数ではない。

Xの一覧APIには既存の枠資格の再評価が含まれる。統合一覧では初回と明示更新・変更後に使い、検索や絞り込みのたびには呼ばない。ユーザーのプラン・支援者資格・枠の割当、受信や送信の可否は引き続きサーバー側で判定する。

## 互換性と運用

既存の `#x-notifications` と受信情報IDを含むリンクは引き続き利用できる。個人用X通知をサーバー共有の一覧に混ぜず、操作中の下書きと変更確認を維持する。プラン・支援画面の表示変更は決済基盤の有効化や価格の変更を伴わない。

画面の本番反映では、既存リリースとビルドを残し、分離したリリースで管理画面をビルドしてから管理画面の参照先を切り替える。Botの起動設定・データベース・決済設定は画面更新のために変更しない。問題が発生した場合は、保存した旧管理画面の参照先へ戻し、管理画面だけを再起動する。Botのリースやデータベースを古いバックアップで上書きしない。
