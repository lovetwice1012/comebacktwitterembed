# Edge の停止中欠落と復旧候補

## 現状

合成試験でWNSの停止中に送った3件のうち、再接続後に保存できたのは1件だった。試験条件と対照結果は [Windows Edge の合成通知試験](windows-edge-synthetic-test.md) を参照する。既存の受信箱は受信後の暗号文を保持できるが、WNSから受け取れなかった通知の内容や対象投稿IDは保持していない。移譲ファイルにもCookieや通知履歴は含まれない。

既存のX展開プロバイダーは、既知の投稿URLから表示用情報を取得する。監視アカウントの投稿一覧を取得して停止中の欠落を復元する経路ではない。Pushに含まれる対象外・不明な通知を自動投稿しない判定も、投稿一覧だけから再現できるとは限らない。

旧版互換のX登録処理は別に存在するが、Xのログイン情報を使い、X側のPush登録を変更する操作であり、実行ごとの明示的な有効化が必要である。複数登録時にXがどの端末へ通知するかや既存登録を維持するかも未確認。この処理を新方式のファイル抽出へ混ぜたり、実アカウントで実行したりしない。

## 公式APIの候補

[X公式の投稿一覧](https://docs.x.com/x-api/posts/timelines/introduction)は、ユーザーIDごとの投稿、ページ送り、期間指定、返信・リポストの除外を提供し、取得件数に上限がある。公式説明では開発者アカウント、アプリ、認証情報が前提となる。[API利用開始の説明](https://docs.x.com/make-your-first-request)にも開発者アプリの認証情報が必要とある。既存アプリの有無、利用可能範囲、費用、監視対象の非公開投稿に対するアクセス権は未確認である。

投稿一覧で見つかった投稿が、その利用者に実際にPush通知される対象だったことは、このAPIの説明からは分からない。削除済み投稿や権限外の投稿も含め、停止中に発生した通知を完全に再現できる根拠はない。元のPushの受信時刻や通知本文も一覧から復元できるとは限らない。したがって投稿一覧をPushとして偽装して既存の受信箱へ投入しない。

## 実装前に必要な確認

- 実際のAPI契約、利用条件・費用、対象アカウントの公開範囲と認証方法。
- 「通知対象だった投稿」と「投稿一覧にある投稿」の差、返信・引用・リポスト・削除済み投稿を含む期待動作。
- 停止期間の安全な記録、ページ送りと取得上限、失敗・制限時の再試行、取得漏れを検出できない場合の扱い。
- Pushと復旧候補の重複判定、利用者・監視登録との対応、現在のプラン設定・購読停止・既存の送信制御の維持。
- 独立した試験用アカウントと合成データで、取得結果と通知履歴の一致を検証すること。

上記は検討事項であり、新しい認証情報の取得やAPI呼び出しを有効化したものではない。正確な復旧方法が確認できるまで、Edge受信の提供は無効のままとする。
