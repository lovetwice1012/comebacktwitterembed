# X通知の公式形式と投稿リンクの確認

2026-10-14（日本時間）。[Xの公式Service Worker](https://x.com/sw.js) の公開ソースと、
本人の受信情報に届いた暗号化データを別々に確認した。
公開ソースは33777バイト、SHA-256は次の値。

```text
240e739c25026bea9e3b616117ef073c5711e4685075975d43dfca414141a361
```

## 実測した投稿通知の構造

所有者を限定したWorker保守診断で、次の構造を確認した。
本文・タイトル・URL・投稿ID・アカウント名・鍵はログやfixtureへ出力していない。
診断は所有者、購読世代、対象の受信行をロックし、稼働中の接続を維持して実施した。
現在のPrimary権限と支援者資格を再確認し、分類情報だけを監査に記録した。

- 外側に文字列のtitle、body、tag、icon、timestampと、dataオブジェクトがある。
- data.typeとdata.scribe_targetは両方ともtweet。
- tagはtweet-に投稿IDが続き、そのIDはdata.uriの投稿IDと一致する。
- data.uriは投稿者ハンドルを含む相対の投稿リンク。
- tweet_idとuser_idは省略されている。表示・分析用の追加フィールドがある。

旧配送経路は試験用のnotificationType・author・urlだけに対応していたため、
このデータをunsupportedとして保持し、配送ジョブを作成していなかった。
プランの確認間隔を変更しても、この形式の不一致は解消しない。

## 配送へ接続する条件

共通のnormalizeXNotificationで、従来形式と実測した形式を受け付ける。
実測形式では次の全条件を要求する。

- data.typeとdata.scribe_targetが厳密にtweetである。
- data.uriがx.comの正規投稿URL、または同じ相対パスである。
- tagが厳密にtweet-とURIの投稿IDを連結した値である。
- tweet_idが存在する場合は、文字列で投稿IDと完全一致する。
- 投稿者ハンドルがURIから確定し、iやintentなどの予約パスではない。
- 私的通知、通話、X Chat、表示しない通知、複数通知の束ではない。

リンクやtweetという単語だけでは配送を許可しない。
いいね、返信、リポスト、未確認の種別を投稿通知へ推測変換しない。
user_id、タイトル、本文、監視の件数から投稿者を推測しない。
日時・アイコン・追加情報はイベントへ転記せず、保存済みの受信日時を使用する。
追加情報を含むJSON全体に64KB、深さ32、8192ノードの上限を設け、
getter、Proxy、循環参照、toJSONを実行せずに検証する。
アイコンの取得や、Xのポーリング・内部API呼び出しは追加しない。

## 保持済みデータの再処理

現在のWorker自身のリース、所有者、購読世代を検査してから、
ACK100のunsupported行を最大20件ずつ読み直す。
新しい共通正規化を通った行だけをreceivedへ戻し、変更と監査を同一取引で保存する。
通知本文は暗号化されたまま保持し、既存の間隔・優先度・送信上限を通す。
プロバイダーのACKや購読を作り直さず、全行の一括リセットもしない。

未確認形式はunsupportedのまま保持する。
プロセス内の有界カーソルで毎tickの再復号を抑え、再起動後は再確認できる。
認識できても監視対象に一致しない通知はunmatchedとして記録し、送信しない。
ユーザー名の修正や新規監視の作成で、過去の対象外通知を自動配送することはない。

## 画面と検証

受信情報には処理待ち、振り分け処理済み、形式確認、復号失敗、対象不一致の件数を表示する。
振り分け処理の件数は、Discordへの送信成功件数とは区別する。
監視のユーザー名は、数字ID・利用枠・購読を保持したまま本人が編集できる。
新規登録では、通知を受け取りたい相手の@ユーザー名を指定する。
数字IDの入力や外部サービスでのID検索は不要で、従来の数字ID登録も保持する。
数字IDを確認していない登録は公開APIでaccountIdをnullとして返す。
既存の20文字列にはサーバー生成の非数値キーを保存し、Xの数字IDとして表示しない。
登録行のID・枠・送信重複判定は従来の識別子を使うため、スキーマ変更はない。
同じ利用者の同じユーザー名は大小文字を区別せず、登録・編集の取引内で重複確認する。
所有者、版番号、監査、ロールバックを検証する。

実測データを元にしたfixtureは、構造だけを残して全値を合成値へ置き換える。
本番暗号文に対するオフライン確認は、新しい正規化が成功したことを示す。
確認した1件は保存済みの監視ユーザー名と一致しなかったため、配送成功の証拠にはしない。
実際に一致する新しい投稿通知と、そのDiscord配送は別に確認する。
