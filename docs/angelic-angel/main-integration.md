- ファイル作成前の説明と同意、X 以外の通知の破棄、ダブルクリックで使える Windows 配布ツール preview.4。
- Windows Node.js の原因を特定したネイティブ TCP 異常への固定ランタイムと起動時切り替え。

## 既存 main との整合性

管理者の支援者管理、権限、更新競合検知、監査履歴と Square の複数請求周期を保持した。支援者管理画面では通常通知・価格通知・間隔短縮用枠に、停止中を含む X 登録を加えて使用数を表示する。

X の標準出力には通常の Bot 展開を使う。既存の通常通知の `expanded` 既定値、既存ルールとテンプレートの既定動作は維持する。必要な場合は `normal` を明示して選べる。

旧管理情報に保存された負数の追加枠は、従来どおり利用可能数を 0 として読む。保存値・監査・更新競合確認の元の値を保持し、新しい付与台帳の不正な負数は受け付けない。

過去の支援枠は記録済みの付与数を引き継ぐ。旧来の期間集計が期限切れになっても、その既得枠は維持する。過去の金額や現在の倍率から枠数を作り直さない。

## 検証と受入範囲

`main-phase0-tests.xml` は実 Rust 比較を含む 199 件が成功し、参照 14 ファイルのハッシュも一致した。最初の実行で Rust 比較用バイナリが隔離先に無かった記録を `main-phase0-tests-initial.xml` に残し、同じ参照から構築済みのバイナリを指定して比較した。

最初の統合試験 `main-integration-tests-initial.xml` は 704 件中 13 件失敗した。原因は通常展開・X の既定 DM・画面への入口の接続不足と、旧管理情報および恒久支援枠との整合性だった。修正後の該当試験は `main-integration-corrections-tests.xml` の 82 件が成功した。最終一式の結果と対象ソースは `main-integration-validation.json` に記録する。

配布 ZIP は 68,653 bytes、SHA-256 `c41a47ecb694cc8afe19ccfab3420d492a5a327b8264cb84b46da9ab1d7325db`。Git 上の改行変換を止め、配布元スクリプトの正確なバイトを維持する。

## 支援者向け提供に必要な運用設定

ソースの既定値は受付・登録・受信とも停止を維持する。提供時は Web と Worker の両方に `X_NOTIFICATION_ROLLOUT=supporters` を設定する。対象は既存の `users.is_donor=1` を持つ利用者であり、プラン名や金額から推測しない。

Web は公開鍵だけを受け取り、秘密鍵は受信 Worker の権限を限定したファイルに置く。現在のプランの確認間隔と特殊枠数は実設定を確認する。`packages/angelic-angel` の固定依存を用意し、ビルドした `dist/autopush.js` と `dist/crypto.js` を含める。

X の公開 Service Worker 形式は投稿リンク候補の検査までを実装した。具体的な新規投稿通知の種別と実購読を確認する受入が残る。候補を推測で配送へ接続せず、未対応の形式は配送しない。詳しくは `x-webpush-adapter.md` を参照。

この統合は本番で実 X 配送が確認できたという意味ではない。運用時の設定・バックアップ・移行・切り戻しは `quota-operations.md`、`support-grant-migration.md`、`server-receiver.md` に従い、実環境の確認結果を別に記録する。
