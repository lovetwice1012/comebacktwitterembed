# X通知セットアップのWebダウンロード

ログイン済みの利用者は `/api/automation/x-setup/download` から PowerShell 配布版 `0.1.0-preview.4` を取得できる。レスポンスは ZIP の添付ファイルで、成功・エラーとも `private, no-store`。この GET はPCの情報や通知ファイルを受信しない。

配布ファイル名は `x-notification-setup-0.1.0-preview.4.zip`、サイズは 68,653 bytes、SHA-256 は `c41a47ecb694cc8afe19ccfab3420d492a5a327b8264cb84b46da9ab1d7325db`。`scripts/build-angelic-setup-package.cjs` の固定された9ファイルと生成マニフェストから、検証済み版と同一の ZIP をメモリ上で再構成する。サーバー側には配布 ZIP を書き出さず、Git 管理外の `artifacts/` にも依存しない。

preview.4は利用者向けの文章を整理した版。保存ツールと登録画面を、できること・操作・次の手順から案内する。確認結果は `positive-copy-review.md` を参照。

新版は他サイトの通知設定の混在時に、Xだけのファイルを保存直前の明示確認で作成できる。共有受信先を通じた他サイト通知の到着可能性・取得可能性・破棄方針を説明する。旧preview.2のZIP・証拠は上書きせず保持する。

デプロイにはビルダー、`fflate`、`client/angelic-setup/` の配布対象9ファイルが必要。`dashboard/next.config.ts` の `outputFileTracingIncludes` はこの経路について必要なファイルだけを列挙している。独自のリリースコピー処理でもこの指定を保持すること。`requireBotModule` の既存ルート解決と同じ構成で、リポジトリルートに `scripts/` と `client/` を置く。既存の `repoRoot()` が `src/providers/` を目印にするため、そのディレクトリを保持する無害な `_loader.js` もトレース対象に含める（配布ZIPには入らない）。Next の standalone 出力を単独で移動する場合もトレース済みファイルの相対構成を保つ。任意の外部パスを指定する環境変数は設けていない。

配布対象は `.gitattributes` の `-text` で改行・BOMを含む元のバイト列を保持する。入力の欠落、シンボリックリンク・ジャンクション、サイズ異常、内容変更、ZIPのサイズ・SHA-256不一致では配布を停止し、秘密や内部パスを含まない日本語の503を返す。ソースを更新しただけでは同じ版として公開されない。新版の公開には配布版を別途検証し、固定された版・サイズ・ハッシュとテストを明示的に更新する必要がある。

入力は9ファイル、各ファイル最大1 MiBに制限し、サイズ検査後の読み取りも上限を超えない。同時ダウンロードは進行中の再構成だけを共有する。成功・失敗後は共有を解除し、次のダウンロードでは再検証するため、永続キャッシュで変更を隠さない。30並列のテストで再構成1回への集約と、後続リクエストの再検証・障害復旧を確認する。

ローカル検証: `node --test --test-concurrency=1 scripts/test/automation-x-setup-download.test.js`。認証前の入力未読、配布版の再現、許可リスト、変更・欠落・リンクの拒否、秘密の除外、添付・キャッシュ制御ヘッダーを確認する。実際のOAuthログイン、本番デプロイ、Firefoxの起動や通知購読の作成はこの検証に含まれない。
