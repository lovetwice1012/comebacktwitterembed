# X自動展開 枠管理・割当の追加仕様

日付:2026-10-14 JST。出典:ユーザーの同日追加指示。本仕様は従来の枠制度記述に優先する。

## 制度

- 1枠=利用者ごとに通知を監視するXアカウント1件。同一Xアカウントを10人が監視すれば10枠。受信購読/UAID/ソケット数と別に計数。
- 共用無料枠:全利用者合計50。無料/有料を問わず利用可能。個人の通常登録上限も1件消費。管理画面で上限変更可能。
- 支援者優先枠:無料枠と独立した全支援者合計100。過去/新規支援者が対象。新規は500円以上で500円につき1枠を付与。買い切り、月額解約で消えない。付与数だけ個人総登録上限に加算。優先枠登録は基本枠と別の追加枠だが個人総上限は常に適用。管理画面で全体100の上限変更可能。
- 旧制度:500〜2500円の商品を1回購入につき1枠。既存の購入回数による付与数をそのまま維持。過去金額を500円/枠で再計算禁止。既存の信頼できる付与カウンターを保持し、不明な購入履歴を捏造しない。
- 有償特殊枠:Basic以上の対象プラン。既存プラン設定に紐付いたプラン別上限。無料/支援者全体プールと独立。個人上限を増やさず通常登録上限1件分を消費。対象外への変更/解約で資格再評価。
- 通常の割当順:共用無料→支援者優先→有償特殊。使える先順位があれば後順位を使わない。支援者枠は支援者のみ、特殊は対象有償のみ。個人上限に達していれば全体空きがあっても拒否。2026-10-15の追加指示により、既存支援者がリアルタイム特典を明示的に選ぶ新規登録は、保有数と全体空きの範囲で支援者優先枠へ直接割り当てる。この経路は個人1枠で、5枠の空きを要求しない。
- 個人総登録上限=現在プラン基本登録上限+保有支援者追加枠数。通常通知とX監視で同じ個人枠を共有。既存の通常通知/有償プラン/確認間隔追加枠を破壊しない。
- 品質・処理優先度・確認間隔・スケジューリングは通常通知と同じ現在のプランから参照。Basic利用者が無料プールを使ってもBasic品質、支援者プランの利用者はXでも支援者プラン品質。プール自体は品質選択に使わない。リアルタイム特典の資格は別に判定する。

## 整合性と管理

DBトランザクションで割当/解放/移動。二重操作は冪等。**既存登録の自動再配置は禁止**。空き発生・登録解除・プラン変更・上限変更では消費種別を変更しない。資格失効時は現在の枠種別と個人予約を保持し、既存の利用停止ポリシーで停止する。停止中も予約枠として使用数に計上する。

移動は所有者または権限のある管理者の明示操作のみ。移動先の空き・資格・個人総上限・種別上限をサーバー側で検証し、移動先確保/移動元解放を原子的に行う。無料/支援者/特殊の新規優先順位は手動移動先の選択を制限しない。設定・対象・処理品質・確認間隔・購読状態・個人枠IDは移動で変更/削除しない。個人上限拒否と全体プール満杯を別コードで説明。

サーバー側で所有者・資格・上限を検証。支援付与は検証済み決済または実管理者操作だけ。決済再送は一意な出所IDで二重付与を拒否。旧既得枠を失わず、枠移動/解放/管理変更を監査。孤立/不正計数を検出。決済基盤を追加有効化しない。

管理者UI:無料/支援者の上限・使用・空き、プラン別特殊上限、利用者保有支援枠、監視の消費種別、変更時整合性、支援/決済/付与履歴。利用者UI:現在プラン、総上限、登録数、支援追加数、X利用可能数、無料空き、具体的拒否理由。既存UIを再利用し内部種別を必要以上に強調しない。
