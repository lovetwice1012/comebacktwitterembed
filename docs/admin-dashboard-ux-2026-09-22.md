# 管理ダッシュボードの操作改善

管理画面を「概要 / 調査 / サーバー・設定 / 分析 / 運用・復旧 / 管理設定」の6区分に統合した。既存の管理操作、緊急復旧、分析、DB参照は各区分から利用できる。旧URLのURL検証・指定先送信・サポート画面も共通の画面構成で開く。

## 調査と設定

- サーバー、チャンネル、対象ユーザー、元投稿、期間、結果分類、記録種別、選択事象をURLに保存する。戻る・再読込で復元する。操作結果・不明な受付は既存の同一受付キーで確認する。
- 投稿リンクから対象を指定できる。サーバー・チャンネル名の候補取得は管理者認証とBot認証を通す。候補取得が失敗してもIDを直接指定できる。
- 一覧は対象、結果、理由、失敗段階、所要時間を表示する。詳細は横に開き、元の一覧を保持する。狭い画面ではカードに切り替える。記録されていない原因や時間は推定しない。
- 選択した事象からサーバー設定や該当URLの検証へ移動する。
- 設定の直接編集タブを統合。説明・型に合うフォーム・現在値と変更後の差分を表示し、確認後に保存する。変更検出用hash、既定値への復元、コピー、操作履歴を維持する。JSON編集は詳細欄で利用する。
- 概要に未解決の障害、最近の失敗、実行中・受付済み操作を表示する。管理API接続とBotのシャード状態は別表示とする。
- 分析にプリセットを追加し、サーバーと期間を共有する。詳細条件もURLに保存する。全体集計や障害・通知には適用されない条件を表示しない。

## 管理APIとの対応

`runs` と `events` にチャンネル・ユーザー・元投稿のフィルターを追加した。`actions` は対象サーバー・チャンネル・ユーザー・元投稿・日時を検索する。条件はSQLのパラメーターとして、ページ送りより先に適用する。root要求の集約テーブルと旧イベント経路の双方に対応する。

検索応答の `appliedFilters` を照合するため、旧版の管理デーモンが新しい絞り込み条件を無視した場合、その結果を絞り込み済みとして表示しない。新UIと管理デーモンは同じリリースで反映する必要がある。DBスキーマ変更はない。

`events/{id}` と `notifications/{id}` の参照を追加し、再読込後の詳細表示を可能にした。既存の管理者認証を使用する。

## 検証

- 管理エージェント: `go test ./... -count=1`。新しい検索条件、双方のroot検索経路、条件適用後のページ送り、値のSQL分離、操作の対象・日時検索を含む。
- フロント: TypeScript型検査、変更対象のESLint、既存のレポート・原文表示テストと新しいURL状態・認証・API互換性テスト。
- Next.js本番ビルドをローカルの検証用環境変数で確認。稼働中サービスや本番DBには反映していない。
- `node scripts/verify-admin-workspace.cjs` は実際のReactコンポーネントをローカルの架空APIで操作する。ブラウザーから外部への通信を遮断する。ローカルのQA用Playwrightと `node_modules/.cache/ux-browser` のChromiumを使用する。
