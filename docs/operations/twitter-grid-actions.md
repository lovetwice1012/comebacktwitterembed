# X の分割投稿操作

画像展開が複数投稿に分かれた場合、Bot は確定済みの投稿 ID と内容の署名を使って操作対象を確認する。別の投稿を推測して操作しない。画像表示の変更・翻訳・削除と公開画像の置換は、同じ gallery の行ロックで直列化する。

新しい分割投稿では、既存ボタンの custom_id に `sl1` と gallery ID を付与する。表示文言は変わらない。ボタンが押された際は DB の一致した記録を必ず検証し、未保存や不整合なら一通だけの操作へ戻さず停止する。送信済みの分割記録は投稿の存続中に期限切れで失われないよう保持し、全体削除が確定した後は既存の30日保管へ戻す。外部で直接削除された投稿の記録は自動削除しないため、必要なら監査したうえで管理する。変更以前の投稿で記録が期限切れになったものは、近接する別投稿を推測して結び付けない。

既存のボタンから届いた情報と現在の投稿が一致しないときは、現在の投稿を本人に確認してもらう。確認は2分間有効で、操作直前にも投稿、利用者、権限を確認する。

表示言語、サイレント送信、過去共有案内、翻訳の表示方法は、既に表示済みの画像の安全条件を変えないため、これらを変更しても画像操作を継続できる。画像の非表示・センシティブ設定、対象者、ボタン権限および未分類の新設定は引き続き照合し、現在の権限も操作時に再確認する。旧形式の記録は、過去の安全条件が同じだと保存済みハッシュから証明できる場合だけ操作を許可し、証明できない場合は元リンクからの再展開を案内する。旧ハッシュは自動で上書きしない。

Discord の編集・削除の前に `bot_twitter_grid_action_intents` へ操作の識別子と確認用 SHA-256 を独立 commit する。本文や翻訳文は保存しない。操作が確定して gallery の更新が commit された後、operation_id を条件に intent を削除する。Discord の応答や DB の commit が不明な場合、次の操作では記録と実際の投稿を照合し、変更が確認できた分だけ整合する。変更前のままでは遅延反映を否定できないため、同じ操作を自動再送しない。

未解決の intent を経過時間だけで削除しない。gallery ID と現在の Bot 投稿を確認し、原因と操作結果を調査する。意図の記録は本文を含まないが、gallery ID、Discord の場所、操作者 ID、時刻および照合値を含む。データ保持と削除の運用は、関連する gallery と未確定の Discord 操作の扱いが確定してから行う。

先頭まで削除した後に DB の commit や応答確認が失敗した場合、定期処理は削除 intent の全パートの ID と署名を照合し、Discord が全 ID に対して「不明なメッセージ」を返す場合だけ記録を整理する。Discord への再削除や再送は行わない。権限不足、通信失敗、429、投稿の残存、記録の欠落や不一致では intent を残し、操作の再送やレコード削除を行わない。参照権限のないチャンネルや長期停止中の Bot では自動照合できないため、運用者が当該投稿と記録を調査する。

この変更は `20261113_add_twitter_grid_action_intents.sql` で intent テーブル、`20261113_add_twitter_gallery_locator_index.sql` で検索用索引を追加する。復旧用の旧版への切り戻し時も、未確定の操作記録を削除・上書きしない。旧版は新テーブルを使わないため、未解決操作がある場合は手動で状況を確認してから切り戻す。

Discord に条件付き edit/delete はない。API 呼び出しの直前に再取得しても、その直後に状態や権限が変わる競合を完全に除去できない。外部で変更された投稿は照合に失敗した時点で操作を止める。

公開画像をまとめた後は、元 X 投稿の識別子・公開状態・センシティブ状態と、保存済み画像の順序を現在の取得結果と照合したうえで、元画像へ戻せる。必要な公開状態を確認できなければ画像を送信しない。取得先は既存の X プロバイダー設定に従う。第三者取得先のキャッシュにより、X 本体の変更が応答に即時反映される保証はない。

画像が10枚を超え、対象がチャンネルの最後の投稿なら先頭を編集し、続きの画像を送信する。新しい発言が後にある場合は、先頭10枚だけを戻す、先頭10枚と別投稿の残りを戻す、全画像を新規投稿として展開する、のいずれかを利用者が選ぶ。引用などで元投稿に10枚収まらないときは、そこに戻せる枚数と追加投稿を示してから処理する。先頭10枚だけ戻した場合も、保存された残りを後から本人が明示的に投稿できる。Discord には末尾確認と送信をまとめる原子的な操作がないため、送信後も間の履歴を確認し、別の発言が挟まった場合はその発言に触れず結果を知らせる。

復旧は既存の gallery 行ロックと intent テーブルを使う。送信前の予定には画像の識別用ファイル名と SHA-256、投稿範囲や保持添付の識別子を記録し、本文は記録しない。応答不明時は同じ POST を再送せず、権限・元投稿・対象メッセージとハッシュを再照合する。履歴を最大500件確認しても一意に特定できなければ操作記録を保持し、手動で確認する。前半だけが確定し後半が未試行と分かる場合は、確認済みの10枚を維持してから、利用者が残りの投稿を明示的に再開できる。復旧・照合は同時2件、各操作90秒を目安に制限する。

復旧は1画像あたり25 MiBと Discord が通知するサーバーの添付上限の小さい方を適用し、1投稿の画像合計は80 MiB以内に分割する。Discord がサイズ超過を確定応答した場合も、順序を保って対象の投稿を細分化する。先頭10枚だけを選んだ操作で追加投稿が必要になった場合は、投稿数を表示して本人の確認を得る。1画像だけでも送れない場合は停止して案内する。応答が不明な場合は再送せず記録を照合する。旧記録に対象・引用の対応を検証できる情報が不足する場合や、取得不能・権限不足で状態を確定できない場合は対象を推測しない。切り戻す際は先に未確定 intent と実際の Discord 投稿を照合し、テーブルや既存 gallery を上書きしない。
