# 機械判定・利用者確認の運用方針

2026-09-22追加指示: 最終的な内容・権利・通知先の判断は利用者が行う。通常は管理者が介入せず、機械的に判定できる違反を拒否する。審査保留は作らない。

## 現行の動作

1. 未接続の意味判定器待ちを、内蔵の決定的な機械チェックに置き換える。
2. 通知は通過／除外／検査処理失敗、公開は通過して即時公開／理由付き拒否とする。検査不能を人の審査待ちにしない。
3. 管理者承認UIを通常フローから外す。通報・緊急停止は例外対応として残す。
4. 利用者による内容・権利・通知先の確認と、機械チェックの限界を表示・記録する。
5. 古い審査待ち・安全保留も、人の承認を待たずに終端状態へ移す。指定時刻・静穏時間・429バックオフなど配信スケジュールは保持する。

## 判定すること／しないこと

- 共通: 不正な構造、秘密URL・既知の資格情報表現、危険なリンク形式・私設アドレス、明示されたセンシティブ属性と宛先の不一致、実行可能添付の代表的な拡張子・ヘッダーを検査する。通常通知の語句照合には、指定された共通辞書と利用者のルールを使う。
- 共有: スキーマ・依存関係・ライセンス記入・権利確認、公開文章・変換後文章・メタデータを追加検査し、既定でスターター禁止語辞書も適用する。禁止語辞書の語そのものは防御用データとして区別する。通常通知へ誤検知の多いスターターを一律強制することはしない。
- 文脈の完全理解、画像・音声・動画の意味判定、外部URLの将来の変更、権利・同意の真正性、全ての違法性は保証しない。
- 「機械チェック通過」は合法・安全認定ではない。0.1%の総合倫理判定精度を達成したとの表示は行わない。今回の指示により、通常運用の解禁条件を未実装の意味判定器や人の承認には依存させない。
- 判定処理が故障した場合は、その操作を失敗として終える。無検査で送信・公開したり、期限なしの審査待ちに残したりしない。
- 公開でスターターを併用するときは独立した照合とする。運営辞書の許可語でスターターを暗黙に解除しない。語彙方針を変更する場合は、運営がスターター併用設定と自前の辞書を明示的に調整する。利用者の共有ルール・辞書から運営側のチェックを弱めることはできない。

責任確認表示は運営側の規約上・法令上の責務を消すものではない。Discordはアプリの不正利用防止、問題の通報経路と適切な対応を開発者にも求める。[Discord Developer Policy](https://support-dev.discord.com/hc/en-us/articles/8563934450327-Discord-Developer-Policy)

本番への移行・実通知はこの変更では実施しない。

配信の既定は `normal` とする。タイトル＋URLを投稿し、
サーバー内の展開はBotの通常機能とサーバーのプロバイダー設定に任せる。
カスタムルールで `expanded` を選ぶと、通知側が展開結果を直接送る。
保存済みルールの明示された表示形式は維持する。
カード・文章・URLだけ・直接展開では、このBotによる同じ通知の再展開を抑止する。

DMは通常展開の対象外なので、`normal` はタイトル＋URLのみを送る。
DMで展開結果が必要な場合は `expanded` を選ぶ。
通知履歴は通知文の送信結果を管理し、通常展開の結果は展開履歴で管理する。
通常展開の成否によって通知文を自動再投稿しない。
他サービスの通常Webhook投稿は従来の設定どおり展開する。
