# NASバックアップからのOCI緊急稼働

この構成は、正常に検証できたバックアップをOCIに準備し、本体の起動許可が失効した場合だけOCIへ役割を移す。設定・保存済みの証拠と、実際に検証した範囲を区別する。savedataを移行しない制約はユーザー承認済み。

## 復旧するもの

既存NASの`host-mysql`バックアップからCBTE DBを復元する。暗号化ファイル、SHA256、サイズ、完了記録、UTC世代名を検証してから、NAS内でOCI専用公開鍵へ再暗号化する。NASの復号用秘密鍵はNAS外へ移さない。転送と復元の途中に平文SQLファイルを作らない。

2026-09-06の実検証では約841MBのバックアップをOCIのMySQL 8.0.42に復元し、CBTEの36テーブル、guilds 17,116件、guild_provider_settings 18,531件などを確認した。復元処理は約70分かかった。これは選択した世代の件数であり、現在の本体件数ではない。

日次バックアップ後に本体へ書かれたデータを復元できる保証はない。使用世代・取得時刻・経過時間・不足範囲は管理画面に表示する。古いsavedataは含まれず、OCI稼働後の新しい保存データだけを公開する。

## 役割と通信

- NAS exporter：検証済み世代の再暗号化・限定ダウンロードと、OCI稼働後の暗号化バックアップ受信。
- NASからOCIへのSSH転送：OCIのloopback上へexporterを転送。家庭側のポート開放とWindows常駐処理は不要。
- authority：OCI上の独立SQLiteに現在の役割・世代・期限付き起動許可を保存する。アプリDBを復元してもこの状態は巻き戻さない。
- guardian：本体とOCIのsystemdサービスを監督する。許可取得前にはBotを起動せず、期限内に更新できなければ対象cgroup全体を停止する。本体では独立した分析・レポートworkerも停止対象にする。
- controller：暗号化取得、候補DBの作成・復元・検証、起動許可の確認、OCI起動、Gateway・DB・公開経路の確認を進める。
- 独立Go管理Web：Bot/Nextとは別のサービス。Discord OAuth、パスワード、パスキーに対応し、復旧状態と履歴を表示する。

本体のSSHにはOCIへ向かう専用接続も用意し、Cloudflare経路と分離する。接続用キーは転送先と転送ポートを制限する。

## 自動切り替えの条件

暗号化ファイルが最新というだけでは稼働させない。復元した候補自身の世代・SHA256・時刻が一致し、許容期間内で、SQL復元と必須テーブル検証が完了していることが必要。

さらに、本体guardianの導入証明、自動切り替えの有効化、旧許可の失効と待機期間、管理者の稼働指示、OCIの実行環境と公開経路の設定を確認する。HTTPエラーやSSH応答停止だけでは起動を許可しない。管理者の停止・保守指示は永続化してから応答し、長時間の復元中も監視する。

起動許可は90秒、終了余裕は20秒、失効後の待機は60秒。authority再起動・時刻異常では150秒以上の隔離期間を置く。途中停止したインポートは続きから再開せず、所有権を確認して隔離する。OCI稼働後は既存DBを使い続け、古い本体バックアップを上書き復元しない。

公開URLを変更する前に、現在のBot PIDと世代に一致する新鮮なGateway ready記録、DB応答、通知隔離処理の完了、現行leaseを確認する。DNS変更は固定したOCI tunnelへの操作に限定し、公開側のnode・epoch・instanceIdが一致するまで成功扱いにしない。本体への自動的な切り戻しはしない。

## 容量とバックアップ継続

既定では前の候補を保持し、容量が足りなければ明示的に止まる。`standbyReplacement: "single"`を指定すると、検証済みの新暗号化ファイルを確保した後、未稼働の候補だけを記録付きで退役させて容量を空ける。元の暗号化ファイル・検証記録は保持する。この更新中に障害が起きた場合は、新候補の復元完了を待つ必要がある。

OCI稼働後もCBTE DBを毎日暗号化してNASへ保存する。未送信成果物の再試行は新しいdumpと分離する。NAS保存先は元の本体バックアップとは別のepoch付き領域で、古い本体のバックアップと混同しない。
