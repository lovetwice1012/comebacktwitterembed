# X の複数画像の展開

X の投稿に複数の画像がある場合、通常の展開では元の順序を保ち、1 通につき最大 10 件の添付に分けて送信します。本文と投稿情報は先頭のメッセージに表示します。続きの送信に失敗した場合、元の投稿は残ります。

「画像をまとめる」から並べ方、画像の収め方、形式、表示先を選べます。詳細設定では列数、画像の幅・高さ、余白、背景色、画質を指定できます。合成は同じ X 投稿の画像全体を対象とし、分割されたすべてのメッセージが確認されるまで実行しません。引用投稿の画像は元投稿とは別に扱います。

保存済み投稿の画像は、添付と元データの対応を確実に確認できる方式を準備中のため、現在は合成ボタンの対象外です。従来の保存済み投稿の表示は利用できます。

初期状態では、まとめた画像は操作した本人にだけ表示されます。公開投稿の置き換えは投稿者、サーバー所有者、Administrator 権限を持つ人が選べます。サーバー管理者は X の設定画面で、置換を全員に許可することもできます。表示先を「投稿を置き換え」に設定した場合も、実際の置換には確認操作が必要です。画像の並べ方・列数・間隔・背景・収め方・サイズ・画質と、ボタンの表示もサーバーごとに設定できます。

サーバー向けの URL 形式の自動通知は、通常の Bot 展開を通して表示します。Webhook の通知登録者は、送信の確定情報から本人と確認できた場合に限り投稿者として扱います。送信結果が不明な場合や確認情報が期限切れになった場合は、投稿者を推測せず管理者などの権限で判定します。DM の URL 通知は現在の Bot 展開ルートを通らず、この操作の対象外です。Webhook の直接展開形式は通常のリンク展開ルートとは異なります。

画像や投稿が削除・変更された場合、権限や表示制限が変更された場合、画像の取得や処理ができない場合は合成を中止します。画像の取得量、画素数、出力サイズ、同時処理数には上限があります。公開置換は Discord の複数メッセージを一括で編集できないため、合成画像を確認後に先頭を更新し、続きのメッセージを処理します。途中で確認できない場合は利用者に状態を知らせます。

データベース移行は `20261113_add_twitter_image_grid_settings.sql` を通常のマイグレーションランナーで適用します。追加列はすべて NULL を許容し、未設定時は既定値を使います。ロールバック時は旧アプリを再起動して追加列を保持できます。運用中の変更を失わないよう、旧版へ戻すためだけに設定テーブルをバックアップで上書きしないでください。
