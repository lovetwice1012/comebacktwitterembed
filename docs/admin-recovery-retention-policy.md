# OCIの容量とバックアップ保持方針

2026-09-06のOCI構成では、ルートファイルシステムは47,321,268,224 bytes（約44.1 GiB）。容量追加を前提にせず、DB復元・稼働用の空き領域を残す。

## 緊急稼働中のDBバックアップ

`active-backup.json` の `keepUploadedBackups` は **1**、`minimumFreeBytes` は従来と同じ **4 GiB** とする。新規dump前後に既存の整理処理が実行される。

削除できるのは、NASから受領したmanifestと世代、バックアップID、候補ID、SHA-256、サイズ、DB名が一致する `UPLOADED` のローカル暗号文だけ。古いローカル記録を `EXPIRED` に更新し、manifestを含む受領記録はすべて残す。`PENDING` とNAS上のデータは削除しない。

確認した直近の復元用暗号文は853,371,535 bytes（約0.795 GiB）。同程度のバックアップと仮定すると、ローカル保持3世代＋作成中1世代＋4 GiBの予約領域には約7.18 GiBが必要になる。保持1世代なら約5.59 GiBとなり、空き6 GiB程度の構成で保持数だけが原因となるdump失敗を避けられる。稼働中のDB成長や未送信データの増加で不足する場合は、4 GiBの予約を削らず、未送信データを保持したまま容量不足を報告する。

## 待機DBを復元するための暗号文キャッシュ

新しい候補のDB復元・検証が完了してから、現在の検証済み世代と、設定した数の退役済み世代を残す。`controller.json` の `keepRetiredCiphertexts` は整数0〜3、既定値は1。他の構成では従来どおり現在＋直前1世代となる。

今回のOCIでは、最新DBの検証完了時に空きが5,625,036,800 bytes（約5.24 GiB）となったため、`keepRetiredCiphertexts=0` とする。NASに残る旧exportのmanifestを照合した上で、退役済みの旧暗号文840,794,562 bytesだけを既存の監査付き整理処理へ渡す。現在の検証済み暗号文は保持する。約6.02 GiBまで空きを戻し、NAS保存確認済みバックアップ1世代と次回dumpが4 GiBの予約領域を侵食しない余地を確保する。

古い暗号文を整理できるのは、次の根拠がすべて揃う場合に限る。

- 所有する候補のreceiptと、完了した `RETIRED` の退役journalが一致し、過去の稼働世代を示すフィールドがない。
- NASのsource、export ID、OCI受信者、サイズ、SHA-256が一致する。
- 新しい候補が隔離状態で検証を完了し、現在・準備済みポインターが一致する。
- 新旧の暗号文を再検証し、削除直前にも候補・ポインター・ファイルの同一性を確認する。

`IMPORTING`、`INITIALIZING`、`ACTIVE`、所属不明の候補に参照される暗号文、未完了ファイル、receiptに対応しないファイルは保持する。候補のreceipt、NAS manifest、退役journalはすべて残す。削除の開始・完了も別journalへ記録し、途中終了後の再実行に対応する。

1回の整理は4ファイル・検証30秒を上限とする。同じ検証済みバックアップの定期確認時にも続きを実行する。所有関係や検証に問題があれば整理だけを保留し、検証済みDB候補を消したり未検証の削除へ切り替えたりしない。DBデータ自体の退役は、既存の所有確認付き退役処理が担当する。

設定変更時に候補や暗号文を手作業で削除しない。進行中の復元を止める再起動もしない。新しいコントローラー実装の読み込みは、復元完了後の計画した再起動で行う。
