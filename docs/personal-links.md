# あとで見る・見返す通知・BOOTH再入荷通知

通常のリンク展開カードに「あとで見る」「あとで通知」を追加しました。
売り切れを確認できるBOOTH商品には「再入荷を待つ」も表示します。
いずれも個人用で、一覧・登録結果は本人だけに表示し、通知は本人へのDMに送ります。

## ダッシュボードから管理する

ヘッダーまたは管理画面の「あとで見る・通知」から `/dashboard/personal-links` を開きます。
サーバー管理権限の有無に関係なく、ログイン本人の保存・通知だけを表示します。

- **あとで見る**: URLから追加、タイトル・タグ・メモを編集、検索・タグ絞り込み・ページ送り・削除。
- **見返す通知**: 日時・タイムゾーンを選んで登録し、通知待ちのURL・タイトル・日時を変更、または解除。
- **再入荷通知**: BOOTHの商品情報からバリエーションを選択して登録し、監視対象のURL・バリエーションを変更、または解除。
- Discordからの登録と同じDB・同じ所有者判定を使うため、両方に変更が反映されます。
- 送信開始済み・送信済み・結果不明の通知は編集しません。編集中にDiscordなどから更新された場合は、上書きせず再読み込みを案内します。
- 送信準備中に予約変更・解除が完了すると、古い配信処理からは送信できません。
- 入力エラー・通信失敗時は編集中の内容を保持します。商品情報の再取得が失敗しても登録内容は消えません。

個人データのAPIは `/api/personal-links/` です。認証済みセッションの本人IDだけを使い、
リクエストによるユーザー指定、別サイトからの更新、過大な入力を拒否します。
Botのリースや内部の配信キーはWebへ返しません。

## あとで見る

- 「あとで見る」でURL・タイトルを保存します。画像・動画ファイルの保存ではありません。
- 登録後の「タグ・メモを編集」でカンマ区切りのタグとメモを編集できます。
- `/saved add url:...` でも登録できます。`title`、`tags`、`note` は任意です。
- `/saved list` で一覧、`query` でタイトル・URL・メモ検索、`tag` でタグ完全一致検索、
  `page` でページ指定ができます。1ページ10件です。
- `/saved edit id:... tags:... note:...` で編集、`/saved delete id:...` で削除します。
  IDは一覧に表示します。同じリンクを再保存しても既存のメモを上書きしません。
- 1人1000件まで、タグ10個・各40文字、メモ1000文字までです。
- 既存のツイート本文・メディア保存機能とは独立しています。

## 見返す通知

- 「あとで通知」から「1時間後」「今日21時（日本時間）」「日時を指定」を選びます。
- 日時指定では `2026-10-01 21:00`、`1h`、`30m` のように入力できます。
  タイムゾーンの初期値は `Asia/Tokyo` で、変更可能です。
- `/remind add url:... when:1h` でも登録できます。
- `/remind list` で予定・送信結果、`/remind cancel id:...` で解除します。
- 選べる日時は現在から1分後〜366日後です。過去の「今日21時」は翌日に読み替えずエラーにします。
  夏時間で存在しない・二通りに解釈できる現地時刻は拒否し、UTCオフセット付きISO日時を利用できます。
- 指定時刻以降にDMします。停止中に到来した予約は通常の再起動後に処理します。
  Discordの制限・通信状態・待ち件数によって遅れる場合があります。

## BOOTH再入荷通知

- 売り切れ商品の展開カードから「再入荷を待つ」を押し、商品全体またはバリエーションを選びます。
  選択肢が多い場合はページ送りできます。
- `/restock add url:...` でも登録できます。任意の `variation` にBOOTHのバリエーションIDを指定できます。
- `/restock list` で監視・通知結果、`/restock cancel id:...` で解除します。
- 初回確認は基準の保存だけで通知しません。その後、売り切れから購入可能への変化を検知すると
  **1回だけ**DMします。再度待つ場合は再登録してください。
- 販売期間外・取得失敗・不明な状態を購入可能と判定しません。バリエーションごとの状態を保持します。
- 公開JSONだけを使い、BOOTHへのログインは不要です。同一商品は購読者間で取得を共有します。
  通常の確認間隔は30分を目安とし、新規登録時は早めに初回確認します。
  既存BOOTH新着監視と全体の取得間隔・429の待機状態を共有します。
- 確認時点での購入可能を通知する機能で、在庫の確保や購入は行いません。

## 通知・保存の扱い

- 有効な見返す通知と再入荷通知は、合計で1人100件までです。
- 登録時にテストDMは送信しません。DM拒否などの失敗は `/remind list` / `/restock list` に表示します。
- 送信前なら解除できます。送信開始後は解除不可であることを返します。
- タイムアウトなどで送信結果が不明な通知は自動再送しません。
  配信前の失敗や明示的なレート制限は待機して再試行します。
- 通知はDBに保存し、DBリースで複数処理からの重複送信を防ぎます。
  バックアップから復旧した古い通知は既存の復旧ポリシーに従って停止します。
- 展開カードの操作情報は30日で期限切れになります。保存済みリンクは利用者が削除するまで保持します。
  期限切れのカードでも、対応URLをコマンドに指定して登録できます。
- ギャラリー・過去の共有表示と併用できます。メディアの表示制限と既存のボタン操作制限は維持します。

## 導入と検証範囲

起動時スキーマと `migrations/20260922_add_personal_links.sql` に5テーブルを追加しました。
新しい3コマンドは既存の起動時登録に含まれ、通知処理もReadyから起動・終了処理で停止します。
本番DBへの移行・デプロイ・実DiscordへのDM送信はこの作業では実施していません。

検証専用ローカルDBと模擬Discordを使うテスト:

```powershell
$env:NODE_ENV = 'test'
$env:AUTOMATION_TEST_DB_PORT = '33619'
node --test scripts/test/personalLinks.test.js scripts/test/personalLinks.sql.test.js
```

保存の競合、本人以外の操作拒否、予約の永続化、解除との競合、送信結果不明時の非再送、
同一商品の取得共有、初回基準、バリエーション別の再入荷判定、カードから保存・DM配信までを検証します。
実際のDiscord画面での表示・DM受信は本番導入後の確認が必要です。
