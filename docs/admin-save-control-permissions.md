# 保存操作の共有制御ファイル

本体のBotと分析workerが異なるUIDで動く構成では、両方に `ADMIN_SAVE_CONTROL_GID` を設定する。値は1〜2147483647の整数で、`write-config.py` が既存の `cbte-admin` アカウントの数値GIDを `bot.env` と `analysis.env` に出力する。リクエスト本文からGIDやパスを指定する経路はない。

対象は `SAVES_DIR/<userID>/.admin-save.lock` と `.admin-save-journal.json`。排他的に開いたファイル記述子に対して所有グループを設定し、継承された名前付きアクセスACLを取り除いた後、0660にする。パスを渡すchmod/chownは行わない。ACL操作も固定の `/usr/bin/getfacl`・`/usr/bin/setfacl` に記述子を渡して実行し、コマンド・パスの入力やrootでの再実行へ切り替えない。

既存ファイルの読み取りでは通常ファイル、単一リンク、inode、設定GID、0660、所有者と所有グループだけのアクセスACLを検証する。シンボリックリンクは拒否する。従来の0600ファイルを読めない場合は `SAVE_CONTROL_PERMISSION` として管理者による修復が必要なことを示し、その場で削除・権限変更しない。不完全なJSONや不明なPIDのロックは処理中／状態不明として保持する。

新規のユーザー・stagingディレクトリだけは、ディレクトリ記述子で共有GIDとsetgid、グループrwxを設定する。他ユーザー・他グループの継承ACLは変更前の実効権限に固定し、otherのビットと継承default ACLを保持する。既存ディレクトリの権限は保存処理から変更せず、配置時の修復処理が担当する。メディアと公開JSONのファイルモード0644は変更しない。

環境変数を設定しないOCI・開発環境では従来どおり0600。共有モードはLinuxとACLツールが必要で、設定やツールが不足した場合は明示的に失敗する。

検証には、通常保存と不完全ロックの回帰テスト、設定生成テストに加えて、OCIの一時ディレクトリでroot→UID 65534→rootの読み書き、別UID 65533への拒否、継承ACLによる権限拡大の防止を確認するテストを用いる。本番のSAVESには触れない。
